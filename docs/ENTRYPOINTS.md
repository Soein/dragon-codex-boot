# 启动入口替换与恢复

下载版首次运行默认启动一次后台扫描，仅处理当前 Windows 账户的桌面、开始菜单程序目录和快速启动目录。播放动画和打开客户端无需等待扫描结束。它针对 `launcher.json` 中配置的客户端；开发机的应用名显示为 ChatGPT，应用包标识是 OpenAI.Codex。

## 操作

1. 用当前账户解压到自己拥有、其他普通账户不能修改的本地目录，双击 `DragonCodexBoot.exe`。程序播放动画，后台扫描和替换入口。
2. 打开 `.integration/report.json` 查看替换、补建、跳过、权限错误和扫描超时。扫描最多 300 秒，下次播放不会自动重复扫描。
3. 新增了个人入口时运行 `Rescan-Entrypoints.cmd`。公共目录和其他账户的入口不受支持；管理员权限也不会扩大范围。
4. 删除、移动程序或不再使用之前，运行 `Restore-Original-Entrypoints.cmd`。它恢复备份，并阻止下次播放自动重装。已被用户改动或删除的快捷方式会保留，原因记录在报告中。

恢复与重新扫描也可使用 `DragonCodexBoot.exe --restore-entrypoints` / `--integrate-entrypoints`，不播放视频。命令行执行会等待入口脚本完成；平常播放的扫描在后台进行。

如果要完全关闭替换，在首次运行前设置：

```json
"AutoReplaceEntrypoints": false
```

`ScanAllLocalDrives` 是保留用于读取旧配置的字段，默认 `false`；旧文件中的 `true` 也不会启用全盘或公共目录扫描。已有替换不会因为关闭配置自动恢复，应先运行恢复文件。

## 匹配与备份

扫描 `.lnk` 的实际目标与参数。对包装应用，读取已安装包的应用清单和 AppsFolder ID；部分目标为空的包装应用快捷方式用 Shell 的 AppUserModel.ID 确认。只凭 ChatGPT / Codex 文件名不能触发替换。ChatGPT 网页 `.url` 和浏览器链接不改。

替换时建立新的快捷方式，避免编辑原 MSIX 链接时遗留激活属性。保留文件名、已有图标、快捷键和窗口样式，清空旧参数，工作目录设为启动器目录。原文件保存在 `.integration/backups/`，原始哈希和安装后哈希记录在 `entrypoints-state.json`。每次替换先持久化记录，再写入文件，并检查写入结果。

恢复只覆盖内容仍与安装后的哈希相同的文件，并重新核对目标和备份的权限与路径。备份必须是本次安装 `.integration/backups/` 下的直属 `.lnk` 文件，路径或校验不符则拒绝恢复；用户改变过的文件不会覆盖。替换通过同目录临时文件完成，避免写穿已有硬链接。程序补建且仍由它持有的快捷方式在恢复时移除。所有日志与备份仅留在本机，不上传到 GitHub。

启动器目录、状态、备份、扫描目录及快捷方式必须由当前账户的 SID 拥有，且其他普通账户没有修改权限。SYSTEM、Administrators 和 TrustedInstaller 的系统权限以及普通账户的只读权限不会单独触发拒绝；祖先目录仅允许创建其他子项也不会单独触发拒绝。会改写现有路径的权限、公共/系统目录、UNC、重解析点和路径别名均被拒绝。权限检查失败时，请从自己账户重新解压到个人本地目录，或先核实目标目录的共享写权限；不要通过授予所有人写权限解决错误。提权进程也执行同样检查，不能代替其他账户管理入口。

## 实际覆盖范围

| 入口 | 行为 |
| --- | --- |
| 用户桌面、开始菜单程序目录中的 `.lnk` | 精确匹配后替换；缺少对应入口时补建 |
| 公共桌面、公共开始菜单、其他用户目录 | 不扫描、不替换；恢复记录涉及这些路径时拒绝并报告 |
| 当前用户快速启动/任务栏目录中的 `.lnk` | 验证私有路径后修改；任务栏缓存可能需要取消固定后重固定 |
| 其他本地固定磁盘上的 `.lnk` | 默认不扫描；显式指定的目录仍须通过相同安全检查 |
| MSIX 注册的所有应用、搜索结果、原固定的开始菜单项 | 仍可能直接激活官方客户端；应取消原固定项，再固定启动器 |
| 直接运行官方 exe、协议、第三方程序内部调用 | 不拦截 |
| 网页 ChatGPT、浏览器书签 | 不替换为本地 Codex 客户端 |
| Windows、回收站、链接目录、运行时/缓存目录、启动器目录 | 跳过；不修改应用包 |

因此这项功能是当前账户内可恢复的快捷方式替换，不能声称所有启动路径都已接管。报告标明 `SearchScope: CurrentUserOnly`，同时保留 `RegisteredApplicationChanged: false`、`StartPinsAutomaticallyChanged: false` 和 `TaskbarCacheRefreshVerified: false`。

## 迁移与卸载

先恢复，再移动文件夹，并从新位置运行或重新扫描。不要只移动 exe：程序需要同目录的视频、配置、脚本和恢复记录。没有系统服务或全局执行钩子；完成恢复、取消自己固定的启动器入口后，可以删除解压目录。恢复遇到用户改动时保留文件，需自己决定这些入口后续指向哪里。

旧版本若改写过公共目录或其他账户的入口，本版会保留这些文件，并在恢复报告的 `Errors` 中列出被拒绝的路径；不会把用户可写的旧状态当成管理员写入指令。先保留旧 `.integration` 记录，由受影响账户或管理员逐一核实路径和官方目标，再通过 Windows Shell 删除旧公共启动器入口并从已安装的官方客户端重新创建。不要以管理员身份重新运行旧版恢复脚本，也不要把未经核实的备份写回公共目录。完成检查和迁移前保留启动器目录，以免仍有入口指向它。

## 高级扫描

脚本支持 `-SearchRoots` 显式指定当前账户拥有且通过上述检查的目录；它不能启用公共、其他账户或整盘扫描。使用它不会补建实际桌面/开始菜单入口，也不会扫描其他磁盘。`-OfficialExecutablePaths` 可额外指定已确认的客户端可执行文件；默认从配置的已安装应用包清单获得目标。`-ScanBudgetSeconds` 可设置 1–1800 秒预算。

回归测试只扫描项目内的隔离目录，不自动修改开发者真实入口。

Windows 对快捷方式身份和重新启动信息的处理参考 [Microsoft AppUserModelID 文档](https://learn.microsoft.com/zh-cn/windows/win32/shell/appids)；客户端也可能使用独立的[应用激活方式](https://learn.microsoft.com/en-us/windows/apps/develop/launch/)，因此快捷方式改写与应用注册接管是不同的覆盖范围。
