# 验证与手动验收

## 自动检查

运行 `scripts/test.ps1`：

- 编译真实 WPF 可执行文件。
- 在创建任何媒体窗口和调用桌面 API 之前执行 `--self-test`。
- 检查 605 个屏幕过渡矩形，以及 12 个固定尺寸居中和客户区边框补偿场景。
- 另外检查关键帧边界与插值、负坐标显示器、非16:9目标窗口的最终填满。
- 拒绝 NaN/无穷大数值、零长度淡入、重复时间、空关键帧、空进程过滤、无效窗口尺寸和额外 shell 参数。
- 在项目临时目录内建立隔离 `.lnk`，检查精确匹配、保留图标、递归发现、重复安装、逐字节备份/恢复、用户改动保留、损坏备份拒绝、恢复后不重装、配置关闭。
- 检查默认根目录仅包含当前用户桌面、Programs 和 Quick Launch，旧全盘配置失效；拒绝公共目录、整盘、UNC、重解析路径、普通账户可写目录及祖先删除权限。只读共享 ACL 和祖先创建子项权限可正常通过；提权环境额外验证所有者不匹配仍被拒绝。
- 向隔离状态注入旧公共路径、非 `.lnk` 目标和目录外备份，确认恢复拒绝越界；用隔离硬链接确认恢复不改写同一文件的其他目录项。测试仅调整新建夹具的 ACL，并明确指定扫描根目录，不修改真实桌面、开始菜单、任务栏或系统 ACL。
- 编译并运行 `WindowsSecurityTests.exe`。纯策略用例覆盖固定包族/发布者、Store 来源、开发注册、安装路径边界、注册空集/混合目标/API 错误，以及进程和窗口绑定变化。策略用例中的构造数据不提供生产白名单或绕过参数。
- 创建项目夹具中的 `OpenAI.Codex_fake/Codex.exe` 无包进程和两个无害 Win32 窗口，让它自报官方应用 ID。真实 `GetPackageFamilyName` 必须返回 `APPMODEL_ERROR_NO_PACKAGE`；生产发现路径必须拒绝它且不移动或缩放其窗口。再检查实际窗口销毁、同进程另一 HWND、进程退出和持有句柄失效。
- 实际调用包枚举及不存在包的原生 API，拒绝把 API 缺失当作成功。存在其他已安装包时读取其元数据，验证 P/Invoke 结构布局成功且该包仍不受信；无可用包时明确输出 `SKIP`，在 `qa/windows-security-tests.json` 标明成功互操作分支未覆盖。
- 在带空格、`&`、`!` 和括号的夹具目录放置同名伪造 Explorer/PowerShell，检查系统 API 解析的 Explorer 启动参数，并实际运行无害系统 PowerShell。两份 CMD 入口调用隔离记录脚本，验证动作、路径引用和系统 PowerShell 身份；不扫描真实用户入口，不启动 Codex。

自动检查不启动真实客户端、不截图，也不解码视频；安全测试只显示和销毁自己创建的无害窗口。打包检查另行验证随附视频的字节哈希。它不能证明官方 Store 客户端的正向接入、媒体解码、DWM 实时缩略图或焦点交接已成功，报告固定保留 `officialStoreWindowChecked: false`。

上述入口测试需要 Windows PowerShell、Windows ACL、NTFS 链接语义和 WScript/Shell COM；在 macOS 上做文本、JSON 或补丁检查不能替代这些运行证据。仓库所在目录本身若允许其他普通账户替换祖先或现有子项，测试会拒绝该环境；应使用可信的本地检出目录，不提供跳过安全检查的参数。

## 手动验收

导入 MP4 并校准配置后，使用普通 Windows 桌面进行以下检查：

1. 客户端关闭时启动：动画播放，客户端出现在其后，最终移除播放层。
2. 客户端已运行时启动：接入原窗口，没有第二个客户端窗口。
3. `Esc` 跳过：播放器退出，已有客户端获得焦点。
4. 客户端启动缓慢：视频在 `HoldAt` 停住，客户端出现后继续。
5. 错误或缺失视频：显示明确错误，不留下覆盖窗口。
6. 不同 DPI 和负坐标副屏：验证实际客户区物理像素尺寸与居中位置。
7. DWM 不可用时：验证淡出后仍交给实际客户端。
8. 在衔接完成后输入文字，确认操作的是实际客户端。
9. 在安装受支持官方 Store 包的桌面上验证启动、已有窗口复用、缩略图和最终焦点；检查包升级或目标退出后不会继续使用旧句柄。包身份 API 失败、开发包、非 Store 安装和无包同名进程应明确失败且不接管窗口。此项需要真实官方包，自动隔离回归不能代替。

快捷方式检查 `scripts/install-start-menu.ps1 -Action Verify` 只验证 `.lnk` 的目标和图标，不证明已经固定到开始菜单。

自动入口替换的验证命令为 `scripts/integrate-entrypoints.ps1 -Action Verify`，结果写入 `.integration/report.json`。它验证文件和元数据，不证明开始菜单/任务栏缓存已经刷新。手动检查首次运行、重新扫描和恢复之后，实际点击各处快捷方式是否走预期入口；确认 `.integration/report.json` 中的失败和扫描限制。测试报告不能代替这些 Windows Shell 验收。
